# Два подхода к тестированию GUI

## Обзор

В проекте реализовано **два подхода** к тестированию GUI с диалоговыми окнами:

### 1️⃣ Подход с `test_mode` (Быстрый)
**Файл:** `tests/test_comprehensive_performance.py`

Диалоговые окна **не показываются** в тестовом режиме.

### 2️⃣ Подход с автозакрытием диалогов (Реалистичный)
**Файл:** `tests/test_gui_with_dialogs.py`

Диалоговые окна **показываются и автоматически закрываются**.

---

## Подход 1: test_mode (Быстрый) ⚡

### Как работает

```python
# Приложение создается с test_mode=True
app = MyApp(test_mode=True)

# В коде используются безопасные методы:
def show_info(self, title, message):
    if not self.test_mode:  # ← Проверка
        QMessageBox.information(self, title, message)
```

### Преимущества ✅
- **Очень быстро** - нет задержек на диалоги
- **Простая реализация** - флаг test_mode
- **Точные замеры** времени - нет артефактов
- **Стабильно** - никаких побочных эффектов

### Недостатки ⚠️
- Не тестирует реальные диалоги
- Не проверяет, что диалоги действительно появляются
- Модифицирует поведение кода

### Когда использовать
- Быстрая проверка производительности
- Регрессионное тестирование
- CI/CD pipeline (быстрые тесты)
- Замеры точного времени выполнения логики

### Запуск
```bash
pytest tests/test_comprehensive_performance.py -v
```

### Критерии
- Время отклика < 500ms (чистое время логики)
- Failure rate < 1%
- Память: линейный рост

## Подход 2: Автозакрытие диалогов (Реалистичный) 🎭

### Как работает

```python
# Приложение создается БЕЗ test_mode
app = MyApp(test_mode=False)  # ← Реальный режим!

# Настраиваем таймер для автозакрытия
def close_message_boxes():
    """Находит и закрывает все QMessageBox"""
    for widget in QApplication.topLevelWidgets():
        if isinstance(widget, QMessageBox):
            for button in widget.buttons():
                if widget.buttonRole(button) == QMessageBox.AcceptRole:
                    button.click()  # ← Автоматический клик!
                    break

timer = QTimer()
timer.setInterval(50)  # Проверяем каждые 50ms
timer.timeout.connect(close_message_boxes)
timer.start()
```

### Преимущества ✅
- **Полная эмуляция** пользовательского взаимодействия
- **Тестирует реальный код** без модификаций
- **Проверяет диалоги** - что они действительно появляются
- **Реалистичные замеры** - включают время на UI

### Недостатки ⚠️
- Медленнее (~100-200ms на диалог)
- Более сложная настройка
- Требует QTest.qWait()

### Когда использовать
- Интеграционное тестирование
- Проверка UX и отзывчивости
- Тестирование диалогов
- Финальное приемочное тестирование

### Запуск
```bash
pytest tests/test_gui_with_dialogs.py -v -s
```

### Критерии
- Время отклика < 1000ms (включая диалог)
- Failure rate < 1%
- Все диалоги автоматически закрываются

## Сравнение подходов

| Аспект | test_mode ⚡ | Автозакрытие 🎭 |
|--------|-------------|-----------------|
| **Скорость** | Очень быстро | Медленнее |
| **Реализм** | Тестовый режим | Полная эмуляция |
| **Критерий времени** | < 500ms | < 1000ms |
| **Диалоги** | Не показываются | Показываются |
| **Код** | Модифицирован (test_mode) | Оригинальный |
| **CI/CD** | Идеально | Допустимо |
| **Отладка** | Проще | Сложнее |

## Примеры использования

### Пример 1: test_mode (быстрый тест)

```python
@pytest.fixture
def app_with_data(qapp):
    app = MyApp(test_mode=True)  # ← Без диалогов
    # ... настройка данных ...
    return app

def test_plot_button_response_time(app_with_data):
    start = time.perf_counter()
    app.on_plot_dimensionless_selected()
    QApplication.instance().processEvents()
    elapsed = time.perf_counter() - start
    
    assert elapsed < 0.5  # 500ms - чистая логика
```

### Пример 2: Автозакрытие (реалистичный тест)

```python
@pytest.fixture
def app_with_data(qapp):
    app = MyApp(test_mode=False)  # ← С диалогами!
    # ... настройка данных ...
    return app

def test_plot_button_with_dialog(app_with_data):
    # Настраиваем автозакрытие
    timer = setup_dialog_auto_closer(interval_ms=50)
    
    try:
        start = time.perf_counter()
        app.on_plot_dimensionless_selected()
        QApplication.instance().processEvents()
        QTest.qWait(100)  # Ждем закрытия диалога
        elapsed = time.perf_counter() - start
        
        assert elapsed < 1.0  # 1000ms - с учетом диалога
    finally:
        timer.stop()
```

## Рекомендации по выбору

### Используйте test_mode (⚡) если:
- ✅ Нужны быстрые тесты
- ✅ CI/CD pipeline
- ✅ Регрессионное тестирование
- ✅ Точные замеры производительности
- ✅ Тестирование логики, а не UI

### Используйте автозакрытие (🎭) если:
- ✅ Интеграционное тестирование
- ✅ Проверка UX
- ✅ Финальное приемочное тестирование
- ✅ Нужно убедиться, что диалоги работают
- ✅ Тестирование полного цикла взаимодействия

### Используйте ОБА подхода:
- ✅ В разработке: test_mode для быстрых проверок
- ✅ Перед релизом: автозакрытие для полной проверки
- ✅ В CI: test_mode для PR checks
- ✅ Nightly builds: автозакрытие для интеграции

## Отладка

### Проблема: Диалоги не закрываются

```python
# Увеличьте интервал таймера
timer = setup_dialog_auto_closer(interval_ms=100)  # Было 50

# Увеличьте время ожидания
QTest.qWait(200)  # Было 100
```

### Проблема: Тесты зависают

```python
# Проверьте, что таймер работает
timer = setup_dialog_auto_closer(interval_ms=50)
print(f"Timer active: {timer.isActive()}")

# Всегда останавливайте таймер в finally
try:
    # ... тесты ...
finally:
    timer.stop()
```

### Проблема: Тесты проваливаются

```bash
# Запустите с детальным выводом
pytest tests/test_gui_with_dialogs.py -vv -s

# Проверьте только механизм закрытия
pytest tests/test_gui_with_dialogs.py::TestDialogClosingMechanism -v -s
```
