# HydraFracApp

HydraFracApp — настольное приложение для интерпретации данных гидродинамических исследований скважин (ГДИС) после многостадийного гидроразрыва пласта (МГРП).
Приложение предназначено для анализа динамики давления и дебита, расчета безразмерных параметров и подбора параметров пласта путем сопоставления с эталонными кривыми.

Проект реализован на Python с использованием PySide6 для пользовательского интерфейса и NumPy для численных вычислений.

---

# Идея проекта

При анализе ГДИС после гидроразрыва пласта необходимо определить параметры системы:

* проницаемость пласта **k**
* полудлину трещины **L**
* skin-фактор
* характер фильтрационного режима

Для этого используются **безразмерные кривые давления и емкости**, а также **производная Бурде**.

HydraFracApp реализует следующий подход:

1. пользователь загружает динамические данные
2. задает статические параметры пласта
3. задает диапазоны оптимизации
4. система вычисляет безразмерные параметры
5. solver сравнивает данные с эталонными кривыми
6. определяется оптимальная модель пласта

# Основные возможности

Текущая версия приложения поддерживает:

### Ввод данных

* загрузку данных из **CSV**
* загрузку данных из **LAS**
* ручной ввод из **буфера обмена (Excel / CSV)**

Поддерживаемые данные:

```
t — время
P — давление
Q — дебит
```

Если дебит отсутствует в данных, он может быть задан как **постоянный параметр**.

---

### Обработка данных

Приложение автоматически рассчитывает:

* перепад давления
  `dP = P0 − P`

* нормированный дебит
  `Q / N`

* безразмерные параметры

```
X — фильтрационный параметр
Y — емкостной параметр
```

* производную **Бурде**

---

### Визуализация

Отображаются графики:

* давление `P(t)`
* дебит `Q(t)`
* безразмерные кривые `X(Y)`
* производная Бурде `dP/dt`

Поддерживаются режимы:

```
linear
log-log
```

---

### Solver

Модуль оптимизации решает обратную задачу интерпретации ГДИС после МГРП, определяя параметры пласта и трещины путём сопоставления фактических данных с эталонными кривыми из базы данных.

#### Принцип работы

Алгоритм использует **гибридный подход**:

1. **Выбор Skin-фактора (Beam Search)** — перебор дискретных значений из библиотеки, выбор top-k лучших

2. **Выбор N (количество трещин)** — для выбранных Skin перебор значений N, выбор лучшей комбинации

3. **Байесовская оптимизация (Optuna)** — оптимизация непрерывных параметров k и xf:
   - Эталонная кривая модифицируется: `y_mod = y_ref * k * (1 + 0.1 * log10(xf + 1))`
   - Сравнение с входными данными **без нормализации**
   - Параметр k влияет на амплитуду и напрямую отражается на ошибке

#### Невязка

- Интерполяция обеих кривых на общую сетку
- Сравнение **реальных значений** (raw, без нормализации)
- Метрики L1, L2, integral по производным (linear, loglog)

#### Результат

Оптимизация возвращает: Skin S, проницаемость k (мД), полудлину L (м), количество трещин N, значение ошибки.

```
 ↓

 ↓

 ↓
Solver
 ↓
Results
```

# Модели данных

### RawDynamicData

Хранит исходные данные пользователя.

```
t
P
Q
is_Q_in_dynamic_input
```

Эти данные **никогда не изменяются**.

---

### ProcessingDynamicData

Рабочая версия динамических данных.

Содержит:

```
t
P
Q
dP
burde
```

Дополнительно может хранить:

```
интерполяцию
экстраполяцию
```

---

### DimensionlessData

Безразмерные параметры:

```
X
Y
```

---

### SolverState

Состояние оптимизации:

```
k_current
L_current
skin_current
residual
norm
compare_by
```

---

### ReferenceCurve

Эталонная кривая из базы данных.

Содержит:

```
dimensionless X,Y
static parameters
```

---

# База эталонных кривых

Эталонные кривые хранятся в SQLite базе:

```
reference.db
```

Структура таблиц:

### dynamic

```
curve_id
elemIdx
t
dP
X
Y
```

### statics

```
curve_id
Skin
h
N
W
L
Q
```

Доступ к базе реализован через:

```
ReferenceCurveDBManager
```
