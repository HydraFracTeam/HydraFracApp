## 1. Введение

### 1.1 Назначение

Настоящий документ содержит спецификацию требований к программному обеспечению (SRS) для системы анализа данных гидроразрыва пласта (ГРП) с графическим пользовательским интерфейсом. Документ предназначен для:

- Разработчиков программного обеспечения
- Тестировщиков
- Менеджеров проекта
- Технических специалистов в области нефтегазовой отрасли
- Заказчиков и конечных пользователей

Документ описывает функциональные и нефункциональные требования к системе, обеспечивая полное понимание ожидаемого поведения и характеристик программного продукта.

### 1.2 Область применения

Программное обеспечение предназначено для анализа данных гидроразрыва пласта (ГРП) при разведке и разработке месторождений нефти и газа. Система обеспечивает:

- Загрузку и обработку данных скважин в форматах CSV и Parquet
- Конвертацию физических параметров в безразмерные величины
- Интерполяцию и экстраполяцию данных с использованием методов машинного обучения
- Визуализацию безразмерных кривых в различных плоскостях отображения
- Анализ режимов течения (билинейное, линейное, псевдорадиальное)
- Сопоставление данных с эталонными кривыми
- Расчет индекса продуктивности скважин
- Экспорт результатов анализа

Программное обеспечение разрабатывается как настольное приложение с графическим пользовательским интерфейсом (GUI) на базе Python и PySide6.

### 1.3 Определения, акронимы и сокращения

#### 1.3.1 Термины

- **ГРП** - Гидроразрыв пласта (Hydraulic Fracturing) - технология увеличения продуктивности скважин путем создания трещин в породе
- **МГРП** - Многократный гидроразрыв пласта (Multi-Stage Hydraulic Fracturing)
- **Скин-эффект** - фактор, характеризующий изменение проницаемости в призабойной зоне скважины
- **Дебит** - объем жидкости (нефти, газа), добываемой из скважины в единицу времени
- **Безразмерные параметры** - параметры, приведенные к безразмерному виду для универсализации анализа
- **X** - безразмерный фильтрационный параметр
- **Y** - безразмерный ёмкостной параметр
- **pD** - безразмерное давление
- **tD** - безразмерное время
- **Индекс продуктивности** - показатель эффективности работы скважины
- **Режим течения** - тип фильтрационного режима (билинейный, линейный, псевдорадиальный)
- **Эталонная кривая** - типичная кривая для определенного режима течения
- **RMSE** - среднеквадратичная ошибка (Root Mean Square Error)
- **MAE** - средняя абсолютная ошибка (Mean Absolute Error)
- **R²** - коэффициент детерминации

#### 1.3.2 Акронимы

- **GUI** - Graphical User Interface (Графический интерфейс пользователя)
- **SRS** - Software Requirements Specification (Спецификация требований к программному обеспечению)
- **API** - Application Programming Interface (Интерфейс программирования приложений)
- **CSV** - Comma-Separated Values (Значения, разделенные запятыми)
- **RBF** - Radial Basis Function (Радиальная базисная функция)
- **GP** - Gaussian Process (Гауссовский процесс)
- **ML** - Machine Learning (Машинное обучение)
- **IQR** - Interquartile Range (Межквартильный размах)
- **UI** - User Interface (Интерфейс пользователя)

#### 1.3.3 Единицы измерения

- **м** - метры
- **м³/сут** - кубические метры в сутки
- **атм** - атмосферы
- **ч** - часы
- **мД** - миллидарси (единица проницаемости)
- **мПа·с** - миллипаскаль-секунда (единица вязкости)

## 2. Общее описание

### 2.1 Перспектива продукта

Программное обеспечение представляет собой независимое настольное приложение для анализа данных гидроразрыва пласта. Система является автономной и не требует интеграции с другими системами, однако может взаимодействовать с внешними источниками данных через загрузку файлов.

#### 2.1.1 Интерфейсы системы

**Входные интерфейсы:**
- Файлы данных в формате CSV или Parquet, содержащие информацию о скважинах
- Параметры пользователя через графический интерфейс (выбор методов, настройки фильтров)

**Выходные интерфейсы:**
- Графические визуализации безразмерных кривых
- Текстовые отчеты с результатами анализа
- Экспортированные файлы данных в формате CSV

**Пользовательский интерфейс:**
- Настольное приложение с вкладками для различных функций
- Интерактивные графики с возможностью масштабирования
- Диалоговые окна для загрузки файлов и экспорта результатов

#### 2.1.2 Функции пользователя

Пользователи системы могут:
- Загружать данные скважин из файлов
- Выбирать скважины для анализа
- Строить графики безразмерных кривых
- Выполнять интерполяцию и экстраполяцию данных
- Анализировать режимы течения
- Экспортировать результаты

#### 2.1.3 Ограничения

- Система работает как однопользовательское приложение
- Требуется операционная система Windows, Linux или macOS
- Необходим Python 3.8 или выше
- Доступ к файловой системе для чтения и записи файлов

### 2.2 Функции продукта

Система предоставляет следующие основные функции:

#### FR-1: Управление данными скважин
- Загрузка данных из CSV и Parquet файлов
- Валидация и парсинг данных
- Группировка данных по скважинам
- Хранение данных в памяти для последующего анализа
- Выбор текущей скважины для анализа

#### FR-2: Конвертация в безразмерные параметры
- Расчет безразмерного фильтрационного параметра X
- Расчет безразмерного ёмкостного параметра Y
- Расчет безразмерного давления pD
- Расчет безразмерного времени tD
- Расчет безразмерной емкости CD

#### FR-3: Визуализация данных
- Построение графиков безразмерных кривых в различных плоскостях
- Группировка графиков по типам (реальные параметры, безразмерные, типовые кривые)
- Отображение X-Y графиков
- Выделение интерполированных и экстраполированных точек
- Интерактивные графики с масштабированием

#### FR-4: Интерполяция данных
- Интерполяция пропущенных значений в безразмерных кривых
- Поддержка нескольких методов интерполяции (RBF, GP, линейная)
- Автоматический выбор лучшего метода
- Оценка качества интерполяции (RMSE, MAE, R²)
- Физически ограниченная интерполяция

#### FR-5: Экстраполяция данных
- Экстраполяция безразмерных кривых в будущее
- Адаптивная экстраполяция с выбором метода
- Оценка качества экстраполяции
- Ограничение экстраполяции физическими законами

#### FR-6: Фильтрация данных
- ML-фильтрация данных (Savitzky-Golay)
- Обнаружение выбросов (IQR метод)
- Сглаживание временных рядов

#### FR-7: Анализ режимов течения
- Автоматическое определение типа режима течения
- Расчет уверенности классификации
- Определение характерного времени перехода
- Поддержка билинейного, линейного и псевдорадиального режимов

#### FR-8: Расчет индекса продуктивности
- Расчет индекса продуктивности скважины
- Оценка эффективности ГРП
- Анализ влияния скин-эффекта
- Расчет общей длины трещин

#### FR-9: Обнаружение переходов режимов
- Автоматическое выявление смены режимов течения
- Анализ производных для детекции изменений
- Определение времени переходов

#### FR-10: Эталонные кривые
- Генерация эталонных кривых для различных режимов
- Сопоставление реальных данных с эталонными кривыми
- Оценка качества сопоставления (R²)
- Построение графиков в log-log масштабе

#### FR-11: Экспорт результатов
- Экспорт данных в CSV формат
- Экспорт отчетов в текстовом формате
- Сохранение результатов анализа

## 3. Специфические требования

### 3.1 Функциональные требования

#### 3.1.1 Управление данными

##### FR-1.1: Загрузка данных из файла
**Приоритет:** Высокий  
**Описание:** Система должна позволять пользователю загружать данные скважин из файлов CSV или Parquet.

**Детали:**
- REQ-1.1.1: Система должна предоставлять диалоговое окно выбора файла
- REQ-1.1.2: Система должна поддерживать форматы CSV и Parquet
- REQ-1.1.3: Система должна выполнять валидацию данных при загрузке
- REQ-1.1.4: При ошибке валидации система должна показывать понятное сообщение об ошибке
- REQ-1.1.5: Система должна обрабатывать файлы размером до 100K строк за время < 5 секунд
- REQ-1.1.6: Система должна группировать данные по скважинам автоматически
- REQ-1.1.7: После загрузки система должна показывать количество загруженных скважин и общее количество измерений

**Входные данные:**
- Путь к файлу (выбранный пользователем)
- Файл в формате CSV или Parquet

**Выходные данные:**
- Список объектов WellTimeSeries
- Информационное сообщение с количеством загруженных данных

**Обработка ошибок:**
- Если файл не найден - показать сообщение об ошибке
- Если формат файла не поддерживается - показать сообщение об ошибке
- Если данные не соответствуют схеме - показать детальное сообщение об ошибке

##### FR-1.2: Парсинг и валидация данных
**Приоритет:** Высокий  
**Описание:** Система должна парсить и валидировать данные согласно схеме WellTimeSeries.

**Детали:**
- REQ-1.2.1: Система должна проверять наличие обязательных полей
- REQ-1.2.2: Система должна валидировать диапазоны значений (Skin: [-10, 50], h > 0, N: [1, 100], и т.д.)
- REQ-1.2.3: Система должна обрабатывать пропущенные значения (NaN)
- REQ-1.2.4: Система должна извлекать параметры скважины (Skin, h, N, W, L, a/L)
- REQ-1.2.5: Система должна создавать временные ряды для каждого набора данных

**Входные данные:**
- DataFrame с данными из файла

**Выходные данные:**
- Список объектов WellTimeSeries или сообщение об ошибке

##### FR-1.3: Выбор скважины
**Приоритет:** Высокий  
**Описание:** Система должна позволять пользователю выбирать скважину для анализа из списка загруженных.

**Детали:**
- REQ-1.3.1: Система должна предоставлять выпадающий список скважин
- REQ-1.3.2: В списке должна отображаться информация о скважине (Skin, N)
- REQ-1.3.3: При выборе скважины система должна обновлять все вкладки с данными этой скважины
- REQ-1.3.4: Система должна сохранять текущий выбор скважины

##### FR-1.4: Отображение загруженных данных
**Приоритет:** Средний  
**Описание:** Система должна отображать загруженные данные в табличном виде.

**Детали:**
- REQ-1.4.1: Система должна показывать таблицу с временными рядами текущей скважины
- REQ-1.4.2: Таблица должна содержать колонки: time, pressure, rate
- REQ-1.4.3: Система должна показывать количество строк в таблице
- REQ-1.4.4: Таблица должна быть доступна только для чтения

#### 3.1.2 Конвертация в безразмерные параметры

##### FR-2.1: Расчет безразмерного фильтрационного параметра X
**Приоритет:** Высокий  
**Описание:** Система должна рассчитывать безразмерный фильтрационный параметр X по формуле:

```
X = (0.00864 * k * h * Δp_i) / (μ * B * Q)
```

**Детали:**
- REQ-2.1.1: Формула должна учитывать параметры скважины (k, h, μ, B) и данные (Δp_i, Q)
- REQ-2.1.2: Система должна использовать значения параметров из данных или значения по умолчанию
- REQ-2.1.3: Система должна обрабатывать случаи, когда Q = 0
- REQ-2.1.4: Результат должен быть массивом значений для каждой временной точки

##### FR-2.2: Расчет безразмерного ёмкостного параметра Y
**Приоритет:** Высокий  
**Описание:** Система должна рассчитывать безразмерный ёмкостной параметр Y по формуле:

```
Y = (Q * B * t) / (24 * φ * c_t * h * L² * Δp_i)
```

**Детали:**
- REQ-2.2.1: Формула должна учитывать параметры скважины (φ, c_t, h, L) и данные (Q, t, Δp_i, B)
- REQ-2.2.2: Система должна обрабатывать случаи, когда знаменатель равен нулю
- REQ-2.2.3: Результат должен быть массивом значений для каждой временной точки

##### FR-2.3: Расчет безразмерного давления pD
**Приоритет:** Высокий  
**Описание:** Система должна рассчитывать безразмерное давление pD как отношение давления к начальному падению давления.

**Детали:**
- REQ-2.3.1: pD = P / Δp_i, где Δp_i - начальное падение давления
- REQ-2.3.2: Система должна обрабатывать случаи, когда Δp_i = 0

##### FR-2.4: Расчет безразмерного времени tD и емкости CD
**Приоритет:** Средний  
**Описание:** Система должна рассчитывать безразмерное время tD и безразмерную емкость CD при необходимости.

#### 3.1.3 Визуализация данных

##### FR-3.1: Построение графиков безразмерных кривых
**Приоритет:** Высокий  
**Описание:** Система должна строить графики безразмерных кривых в различных плоскостях отображения.

**Детали:**
- REQ-3.1.1: Система должна поддерживать построение графиков:
  - pD(X) - безразмерное давление от фильтрационного параметра
  - dpD/dY(X) - производная безразмерного давления
  - tD(Y) - безразмерное время от ёмкостного параметра
  - CD(X) - безразмерная емкость
  - X-Y график
- REQ-3.1.2: Пользователь должен иметь возможность выбирать, какие графики отображать, через чекбоксы
- REQ-3.1.3: Графики должны быть интерактивными с возможностью масштабирования
- REQ-3.1.4: Система должна отображать реальные параметры (P, Q) если выбран соответствующий чекбокс
- REQ-3.1.5: Система должна отображать расчетные X и Y если выбран соответствующий чекбокс
- REQ-3.1.6: Система должна выделять интерполированные точки на графике (если была проведена интерполяция)
- REQ-3.1.7: Система должна отображать экстраполированные данные (если была проведена экстраполяция)
- REQ-3.1.8: Время построения графика должно быть < 500ms

**Входные данные:**
- Данные текущей скважины (WellTimeSeries)
- Выбор пользователя (чекбоксы)

**Выходные данные:**
- Интерактивный график с выбранными кривыми

##### FR-3.2: Группировка графиков
**Приоритет:** Средний  
**Описание:** Система должна группировать графики по типам для удобства отображения.

**Детали:**
- REQ-3.2.1: Система должна группировать графики на следующие категории:
  - Реальные параметры (P, Q)
  - Безразмерные кривые (pD, dpD, tD, CD, X-Y)
  - Типовые кривые (Грин-Ягеры, Cinco-Ley, Valko)
  - Специальные пространства (G-функция, MBT)
- REQ-3.2.2: Графики из разных групп должны отображаться на одном графике с различными цветами

##### FR-3.3: Отображение эталонных данных
**Приоритет:** Средний  
**Описание:** Система должна отображать эталонные данные для сравнения, если они загружены.

**Детали:**
- REQ-3.3.1: Если пользователь загрузил файл для валидации, система должна отображать эталонные данные на графике
- REQ-3.3.2: Эталонные данные должны отображаться отличным цветом/стилем
- REQ-3.3.3: Система должна проверять, что эталонные данные отличаются от текущих данных

#### 3.1.4 Интерполяция данных

##### FR-4.1: Интерполяция пропущенных значений
**Приоритет:** Высокий  
**Описание:** Система должна выполнять интерполяцию пропущенных значений (NaN) в безразмерных кривых.

**Детали:**
- REQ-4.1.1: Система должна определять наличие пропущенных значений в данных давления
- REQ-4.1.2: Если пропусков нет, система должна информировать пользователя, что интерполяция не требуется
- REQ-4.1.3: Система должна выполнять интерполяцию в пространстве безразмерных параметров (pD от Y)
- REQ-4.1.4: Система должна использовать несколько методов интерполяции и выбирать лучший
- REQ-4.1.5: Поддерживаемые методы: RBF (Thin Plate Spline), GP (Гауссовский процесс), линейная регрессия
- REQ-4.1.6: Система должна рассчитывать метрики качества (RMSE, MAE, R²) для каждого метода
- REQ-4.1.7: Система должна выбирать метод с наименьшим RMSE
- REQ-4.1.8: Интерполяция должна выполняться с учетом параметров скважины (Skin, N, a/L)
- REQ-4.1.9: Время интерполяции должно быть < 2 секунды для средних данных
- REQ-4.1.10: Система должна восстанавливать физические величины из безразмерных после интерполяции

**Входные данные:**
- Данные текущей скважины с пропущенными значениями

**Выходные данные:**
- Восстановленные данные давления
- Отчет с результатами интерполяции (метод, RMSE, качество)

##### FR-4.2: Оценка качества интерполяции
**Приоритет:** Высокий  
**Описание:** Система должна оценивать качество интерполяции с использованием метрик.

**Детали:**
- REQ-4.2.1: Система должна рассчитывать RMSE для каждого метода
- REQ-4.2.2: Система должна классифицировать качество:
  - Отлично: RMSE < 0.01
  - Хорошо: RMSE < 0.1
  - Удовлетворительно: RMSE >= 0.1
- REQ-4.2.3: Если загружены эталонные данные, система должна рассчитывать метрики относительно эталона
- REQ-4.2.4: Метрики относительно эталона: RMSE, MAE, MAPE, R², максимальная ошибка, медианная ошибка

##### FR-4.3: Физически ограниченная интерполяция
**Приоритет:** Средний  
**Описание:** Система должна обеспечивать интерполяцию с учетом физических ограничений ГРП.

**Детали:**
- REQ-4.3.1: Интерполяция должна учитывать физические ограничения (положительность давления, дебита)
- REQ-4.3.2: Интерполированные значения не должны выходить за разумные физические границы

- REQ-5.1.3: Количество экстраполированных точек должно быть настраиваемым (по умолчанию 20)

- REQ-5.1.5: Система должна рассчитывать метрики качества экстраполяции (RMSE, если есть эталон)

## 4. Приложения

### 4.1 Примеры данных

#### 4.1.1 Формат CSV файла

Пример структуры CSV файла:

```csv
Skin,h,N,W,L,a/L,ElemIdx,X,Y,t,P,dP,Q
0.5,10.0,5,0.01,50.0,0.2,1,0.01,0.001,0.0,100.0,0.0,100.0
0.5,10.0,5,0.01,50.0,0.2,1,0.015,0.002,1.0,98.0,2.0,95.0
...
```

#### 4.1.2 Обязательные поля

- **Skin** - фактор скин-эффекта (float, диапазон: -10 до 50)
- **h** - толщина пласта в метрах (float, > 0)
- **N** - количество трещин (int, диапазон: 1 до 100)
- **W** - ширина трещины в метрах (float, > 0)
- **L** - длина трещины в метрах (float, > 0)
- **a/L** - отношение a/L (float, диапазон: 0 до 1)
- **ElemIdx** - индекс элемента (int, >= 1)
- **t** - время в часах (float, >= 0)
- **P** - давление в атмосферах (float, > 0)
- **Q** - дебит в м³/сут (float)

#### 4.1.3 Опциональные поля

- **X** - безразмерный фильтрационный параметр (float)
- **Y** - безразмерный ёмкостной параметр (float)
- **dP** - изменение давления в атмосферах (float)

### 4.2 Формулы расчетов

#### 4.2.1 Безразмерный фильтрационный параметр X

```
X = (0.00864 * k * h * Δp_i) / (μ * B * Q)
```

где:
- k - проницаемость (мД)
- h - толщина пласта (м)
- Δp_i - начальное падение давления (атм)
- μ - вязкость (мПа·с)
- B - объемный коэффициент
- Q - дебит (м³/сут)

```
