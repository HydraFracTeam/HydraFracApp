Итак, логика загрузки пользовательских данных.

Т.к. пользователь выполняет анализ ГДИС, то мы работаем с одним загруженным сэмплом в текущей версии.
Входящие данны сначала загружаются в pydantic модели, т.к. там встроенные механизмы валидации.
После ввода используются датаклассы для быстрых расчетов.


## Этап 1 Загрузка динамических параметров.
Пользователь должен загрузить файл csv, в котором содержатся 2 обязательных столбца: давление "P", время "t".
Минимальное кол-во точек для t - 20. t пропуски иметь не может, P пропуски иметь может. Длина массивов должна быть одинаковая. Если длина массивов разная, то должна вызываться ошибка. t должен идти монотонно вперед. Если есть дубликаты то удаляем их. 
Если есть третий столбец дебит "Q", то загружаем его тоже и запоминаем этот факт в переменную по типу is_Q_in_dynamic_input = True. Если массива нет, то запишем это в переменную по типу is_Q_in_dynamic_input = False и идем дальше.  Он тоже может иметь пропуски, длина массивов тоже должна быть одинаковая, иначе ошибка. 
Все значения должны быть положительными.

После загрузки мы сохраняем эти 2(3) стобца в модель RawDynamicDataInput: P(давление, кгс/см2): list[float], t(время, часы): list[float], Q (дебит): list[float] | None
Так мы сохраним данные из файла и дальше пользователь переходит к этапу ввода №2: статичные параметры

## Этап 2.
Пользователю открывается вторая часть ввода данных: spinBoxes для всех статичных параметры активириуются и вводятся данные для: длины пласта W, толщины пласта h, вязкости mu, пористости phi, объемного коэффициента B, Сжимаемости системы ct, Кол-ва трещин N.
Эти поля вводятся все обязательно каждый раз через gui.
Еще мы смотрим на поле is_Q_in_dynamic_input и если оно False, то мы также включаем поле для дебита как статичного параметра и ожидаем ввод. Если поле False, то мы ничего не включаем и идем дальше, т.к. Q уже есть.
После ввода пользователь нажимает кнопку по типу ввести "ввести статичные параметры". И тут происходит проверка на то, что все параметры введены, все положительные и прочие проверки на адекватность ввода (объемный коэффициент не может быть больше 1, к примеру).

И все эти данные пишутся в модельку InputStaticParams: mu: float, B: float, ..., Q: int | None.
Если мы ввод дебита ввели через статичные параметры, то мы обновляем в нашу текущую добавляем в RawDynamicData дебит как RawDynamicData.Q = [InputStaticParams.Q]*len(t) или типа того, просто представляем, что такое значение дебита было всегда.
Если никаких ошибок нет, то переходим к этапу 3, открывается меню ввода границ для оптимизируемых параметров.

# этап 3.
Просто вводим для проницаемости k и полудлины трещины L минимальную и максимальную границы для каждого параметра.
Пользователь жмет кнопку, проверяем на адекватность, max>=min, все позитивные и т.д.
После пишем в 3 модельку: OptimizeThresholds: L_min: float, L_max: float, k_min: float, k_max: float. 


# формирование оригинальных данных.
Теперь, когда есть все данные от пользователя, то мы формируем модель текущих данных, с которыми мы работаем в модели CurrentFactData, которая в начале копирует все данные из RawDynamicData (P, t, Q), InputStaticParams(W, h, B, ct, mu, phi), OptimizeThresholds (L_min, L_max, k_min, k_max) и после мы добавляем поля X, Y, Skin_current, L_current, k_current, P_extra (массив для показа экстраполированных значений), X_extra, Y_extra и прочие. Пока план такой, но в целом новые или нужные данные могут храниться здесь.
Для референсных кривых будет отдельная моделька, эта модель касательно непосредственно пользовательских данных.
