# Тестирование ML-функций для анализа данных ГРП

## Обзор

Этот документ описывает подход к тестированию ML-функций и проверке физической адекватности результатов в приложении для анализа гидравлического разрыва пласта.

## Созданные файлы

1. **`tests/test_ml_methods.py`** - тесты для ML-функций
2. **`create_test_data.py`** - скрипт для создания тестовых данных с "побитыми" значениями

## Запуск тестов

### Создание тестовых данных

```bash
python create_test_data.py
```

Этот скрипт создаст:
- Синтетические данные скважин с различными проблемами (выбросы, пропуски, шум)
- Тестовые случаи для ML-функций с разными типами сигналов
- Визуализацию созданных данных

### Запуск тестов ML-функций

```bash
python -m pytest tests/test_ml_methods.py -v
```

или

```bash
python tests/test_ml_methods.py
```

## Проверка физической адекватности результатов

Тесты проверяют следующие аспекты физической адекватности:

### 1. Интерполяция

- **Сохранение диапазона значений**: Интерполированные значения должны оставаться в физически обоснованном диапазоне
- **Корреляция с базовым сигналом**: Результаты должны коррелировать с базовым (неискаженным) сигналом
- **Заполнение пропусков**: Все NaN значения должны быть заполнены
- **Сохранение тренда**: Интерполяция не должна менять общий тренд данных

### 2. Фильтрация

- **Улучшение корреляции**: После фильтрации корреляция с базовым сигналом должна улучшаться
- **Сохранение амплитуды**: Фильтрация не должна значительно менять амплитуду сигнала
- **Отсутствие артефактов**: Фильтрация не должна создавать новые выбросы или артефакты
- **Сохранение физических ограничений**: Результаты должны соответствовать физическим ограничениям (например, давление не может быть отрицательным)

### 3. Обнаружение выбросов

- **Чувствительность**: Должны обнаруживаться явные выбросы
- **Специфичность**: Нормальные колебания не должны определяться как выбросы
- **Разумная доля выбросов**: Количество обнаруженных выбросов должно быть разумным (обычно <20%)

### 4. Комплексная очистка данных

- **Улучшение качества данных**: После очистки корреляция с базовым сигналом должна улучшаться
- **Сохранение физического смысла**: Очищенные данные должны сохранять физический смысл и тренды

## Визуализация результатов

Тесты создают визуализации в директории `tests/test_results/`:

- Графики сравнения оригинальных и обработанных данных
- Визуализация обнаруженных выбросов
- Сравнение разных методов фильтрации и интерполяции

## Типы тестовых данных

### Синтетические данные скважин

- **Скважина с выбросами**: Имитирует ошибки измерений
- **Скважина с пропусками**: Имитирует отсутствие данных
- **Скважина с шумом**: Имитирует зашумленные измерения

### Тестовые сигналы для ML

- **Синусоида с шумом**: Периодические колебания
- **Линейный тренд**: Монотонное изменение
- **Ступенчатая функция**: Резкие изменения состояния
- **Экспоненциальный спад**: Имитация падения давления
- **Логарифмический рост**: Имитация накопления эффекта

## Рекомендации по добавлению новых тестов

1. Добавьте новый тестовый случай в `create_test_data.py`
2. Создайте новый тестовый метод в `tests/test_ml_methods.py`
3. Определите критерии физической адекватности для нового метода
4. Добавьте визуализацию результатов

## Интеграция с CI/CD

Для автоматического запуска тестов при коммитах можно добавить в CI/CD конфигурацию:

```yaml
test_ml_methods:
  script:
    - python create_test_data.py
    - python -m pytest tests/test_ml_methods.py -v
  artifacts:
    paths:
      - tests/test_results/
      - tests/test_data/
```
